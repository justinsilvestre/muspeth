# Import scripts

- Keep each import's conversion logic in pure, unit-tested modules, and keep its entry point a thin layer that fetches data and writes it.
- Reach the database through `scripts/d1.ts`, so that every import honours the `--remote` flag and defaults to the local database.
- Write SQL that can be re-run safely: upsert rows, or replace the rows a previous run of the same import wrote.
- Keep quality problems in the data as quality flags instead of dropping records. Records that report no observation at all, such as ones generated by a language model, are left out: they are not observations, so there is nothing to flag.
