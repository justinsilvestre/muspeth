# The first version

This document describes the first version of the app: where it is served, what each of its views shows, and where its code lives. The second version is being built alongside it under `/v2`, and shares its color scheme setting.

## Addresses

Every page of the first version is served under `/v1`.

| Address | View |
|---|---|
| `/v1` | Connections, before an organism is chosen |
| `/v1/organisms/:nodeId` | Connections of one node. The node ID is URL-encoded, so `wikidata:Q509308` becomes `wikidata%3AQ509308`. |
| `/v1/paths?from=&to=` | Paths between two nodes |
| `/v1/places?near=lat,lon&radiusKm=&from=&to=` | Places and periods |
| `/v1/kinships?organism=` | Several trees, with one organism selected |
| `/v1/taxonomy` | Taxonomic tree |

The Connections, Paths, and Places and periods views also take the repeatable connection filter parameters `kind`, `basis`, `source`, `flaggedWith` and `notFlaggedWith`. Links between nodes keep these filters and drop the other parameters.

The first version was served at the root before the versions existed. So that links shared then keep working:
- the root address `/` redirects to `/v1`;
- any other address outside `/v1` and `/v2` redirects to the same path under `/v1`, keeping its query and fragment.

## Views

- **Connections** lists a node's connections to its neighbours, grouped by kind, with the sources and quality flags of each. A search box finds nodes by any of their names, in any language.
- **Paths** finds the paths of up to four steps between two nodes. Paths rank higher when they avoid hubs, the nodes with many neighbours, and when they mix different kinds of connection. Selecting a node in the drawing offers a new search from it or to it.
- **Places and periods** finds the connections recorded near a place, within a period, or both. A map marks the places with connections, and a timeline counts connections by date. Clicking the map or brushing a period on the timeline narrows the search.
- **Several trees** groups the same organisms once by descent and once by each kind of connection, and sets the trees side by side. Two organisms are close in a kind when they share many neighbours through it.
- **Taxonomic tree** draws the lineages of the GBIF backbone taxonomy as a 3D tree that can be turned and zoomed. Pointing at a branch or leaf shows the names along its lineage.

## Data each view reads

The node list, the sources and the taxonomy depend only on the deployed data, so the first version reads them from precomputed files instead of the Worker (see the README's section on deployment).

| View | Reads |
|---|---|
| All views | `/api/nodes`, precomputed |
| Connections | `/api/nodes/:id/connections` |
| Paths | `/api/paths` |
| Places and periods | `/api/connections`, `/api/connections/places`, `/api/connections/dates` |
| Several trees | `/api/kinships`, precomputed |
| Taxonomic tree | `/api/taxonomy`, precomputed |
| Filters panel | `/api/sources`, precomputed |

## Code

- `src/client/v1/` holds the first version's frontend. `V1App.tsx` lays out the page and routes to the views, which live in folders named after them, such as `paths/` and `places/`.
- `src/client/App.tsx` routes each version's prefix to its app, and redirects the other addresses.
- `src/client/theme/` holds the color scheme setting, which both versions share.
- Links inside the first version build their addresses with `v1Path` (`src/client/v1/v1Path.ts`), so that each stays under `/v1`.
- The end-to-end tests in `e2e/` exercise the first version, except `e2e/versions.spec.ts`, which checks the redirects and the second version's placeholder.
