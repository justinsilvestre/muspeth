# Quality flags

This document explains the quality flags that records in the graph carry: what each one means, which import sets it, and how common it is. The flags and their one-line meanings are defined in [`src/shared/qualityFlags.ts`](../src/shared/qualityFlags.ts). Counts were taken from `db/muspeth.sqlite` on 2026-10-26.

## Why records are flagged instead of dropped

Each import translates a source's names and claims into the graph's own identifiers and six kinds of connection. That translation is not always exact. A source may name an organism that no taxonomy recognises, report a link for a whole genus, or state a fact without a reference.

The graph keeps such records and marks each doubt with a flag, following the rule in [connection-graph-plan.md](connection-graph-plan.md#rules): flag noise, do not delete it. Each view or creative piece then decides whether to hide flagged records, show them, or make them its subject. A flag therefore records a step in which a source was interpreted. It is not a verdict that the record is wrong.

One kind of record is left out rather than flagged: a record that reports no observation at all, such as text generated by a language model. There is nothing in it to flag.

## Where flags appear

Flags are stored in two places, each as a JSON array of flag names:
- on **connections**, in `connections.quality_flags`;
- on **taxon placements**, in `taxon_placements.quality_flags`, which record how an organism was placed in the GBIF backbone taxonomy.

| Records | In all | With at least one flag |
|---|---|---|
| Connections | 20,910 | 12,010 |
| Taxon placements | 1,907 | 368 |

A record can carry several flags. For example, a story motif linked to a genus by matching its text carries both `text_match` and `derived_from_coarser_level`.

In the app:
- each flagged connection lists its flags with their meanings, in the Connections, Paths and Places views;
- the Filters panel offers three choices for each flag: show flagged connections alongside the others, show only flagged connections, or hide them;
- the API takes the same choices through the repeatable `flaggedWith` and `notFlaggedWith` parameters;
- the Taxonomic tree marks an organism as "placement uncertain" when its placement carries `higher_rank_match`, `fuzzy_name_match`, `doubtful_usage` or `globi_lineage_hint`. A synonym alone does not count, since GBIF resolves it to an accepted name.

## Flags on connections

### Doubts about which organism is meant

These flags arise when an import matches a source's name for an organism to one identifier in the graph.

| Flag | Meaning and when it is set | Set by | Connections |
|---|---|---|---|
| `placeholder_species` | The source names the organism only by a placeholder, such as "Aedes sp." or the unnamed morphospecies "Chironomus sp. 3". The import keeps it as a node of its own, scoped to its network, since two networks' "Aedes sp." need not be the same species. | Mangal | 1,119 |
| `unmatched_name` | The source gives a name that it could not match to a known taxon. The node keeps the source's name and identifier. | Mangal (741), GloBI (8), FungalTraits (2), EltonTraits (1) | 752 |
| `fuzzy_name_match` | GBIF matched the organism's name only approximately, for example despite a spelling difference. | GBIF sound recordings (10), EltonTraits (5) | 15 |
| `synonym_name` | GBIF lists the organism's name as a synonym of another accepted name. | GBIF sound recordings | 11 |
| `trait_name_synonym` | The trait database lists the organism under a different name that GBIF treats as the same taxon. | EltonTraits (6), FungalTraits (1) | 7 |
| `ambiguous_wikidata_id` | Several Wikidata items fit the organism's name equally well, and the import chose one by a fixed rule. | GloBI | 2 |

### Claims that were extended or inferred

These flags arise when a connection says a little more, or something a little different, from what its source states.

| Flag | Meaning and when it is set | Set by | Connections |
|---|---|---|---|
| `derived_from_coarser_level` | The source reports the link for a coarser taxon, such as a genus, and the import attached it to organisms within that taxon. See [Linking to organisms within a taxon](#linking-to-organisms-within-a-taxon). | WOLD (3,411), Thompson motifs (1,567), Wikidata depictions (1,165), FungalTraits (204), the Met (108) | 6,455 |
| `text_match` | The link was found by matching an organism's name in the source's text, not stated as data. For example, a motif whose title contains "pine", or a vernacular name that shares a word with another. | Thompson motifs (1,659), GBIF vernacular names (1,439), Cleveland Museum of Art (119) | 3,217 |
| `unreferenced_statement` | Wikidata states the fact, such as "found in taxon" or "depicts", without citing a reference. | Wikidata depictions (1,255), Wikidata compounds and products (176) | 1,431 |
| `tied_nearest_neighbour` | In a likeness link, several organisms were exactly as alike in traits, and a fixed rule picked this one. | FungalTraits | 188 |
| `uncertain_borrowing` | The World Loanword Database rates the word's borrowing as uncertain. | WOLD | 37 |
| `informal_group_name` | The source names a host only by an informal group, such as "mosses" or "scale insects", and the import read it as the one taxon that covers the group, keeping the group's name as an English name of the node. | FungalTraits hosts | 943 |

### Provenance

| Flag | Meaning and when it is set | Set by | Connections |
|---|---|---|---|
| `duplicate_network_copy` | The connection comes from a Mangal network that is a copy of one also held elsewhere, usually Web of Life. The graph keeps one copy and records the others as provenance; see [datasets.md](datasets.md#duplicate-networks). | Mangal | 3,341 |
| `hand_entered_sample` | The connection was typed in by hand as part of the seed sample, not imported. | The sample | 4 |

### Flags that no record carries yet

| Flag | Intended meaning | Status |
|---|---|---|
| `suspected_error` | The record is likely wrong, for example because it is biologically implausible. | The Mangal import sets it when two different nodes of a network resolve to the same organism, which makes a link from the organism to itself. No current record does this. |
| `sampling_bias` | The source is known to over- or under-represent some organisms or places. | No import sets it. Known biases, such as GBIF holding 14 times more matsutake records from Sweden than from Japan, are described in [datasets.md](datasets.md) but not attached to records. |

## Flags on taxon placements

The taxa import places every organism in the GBIF backbone taxonomy by asking GBIF to match its name. These flags describe that match. They appear on placements, not connections, though the GBIF sound import sets the first two on connections as well.

| Flag | Meaning | Placements |
|---|---|---|
| `higher_rank_match` | GBIF could match the name only to a taxon above its own rank, such as the genus of an unknown species. | 162 |
| `synonym_name` | GBIF lists the name as a synonym, and the organism is placed under the accepted name. | 152 |
| `fuzzy_name_match` | GBIF matched the name only approximately. | 71 |
| `doubtful_usage` | GBIF doubts the taxon it matched, often because it has replaced that record. | 23 |
| `globi_lineage_hint` | Several taxa fit the name, and the match was chosen using the lineage that GloBI gives for it. | 4 |

## Linking to organisms within a taxon

`derived_from_coarser_level` is the most common flag, on nearly a third of all connections, so its rule deserves a fuller description. Several sources speak about organisms at a coarser level than the species:
- a word or story motif usually names a *folk taxon*, such as "pine" or "bee", which corresponds to a genus or family;
- FungalTraits describes the lifestyle of each fungal genus, not each species;
- Wikidata and museum records may say that an artwork depicts a genus.

When the graph holds an organism at exactly the source's rank, the link goes to that organism and carries no flag. Otherwise the import links the source's taxon to organisms within it, preferring the coarsest ones and then the most connected, up to a fixed limit, and flags each link. As a result, a single loanword for "pine" can connect to several pine species. Whether that is useful or misleading depends on the question being asked, which is why the link is kept and marked rather than dropped or left unmarked.

## Adding a flag

To add a flag:
1. add it, with a one-sentence meaning, to `src/shared/qualityFlags.ts`;
2. set it in the import's pure conversion module, with a unit test for the condition;
3. add a row for it to this document.

No migration is needed, since flags are stored as JSON.
